# Frankenstein v0.2 Qualified Integration Specification

This document defines how Bride-qualified mechanisms may enter the production candidate. It is subordinate to the README architecture contract and to the permanent promotion and experiment ledgers.

## Entry condition

The integration branch is cut only from a Bride head where:

1. the real Frankenstein donor suite is green,
2. the mechanism's stage-two controls are green,
3. any required production bridge is green,
4. historical truth, architectural authority, replay, and identity gates pass,
5. the current verdict is PROMOTE or ADAPTER_ONLY,
6. the mechanism is not still blocked by a model-dependent reproduction requirement.

The first intended integration branch is `candidate/v0.2-qualified-integrations`.

## Non-negotiable invariants

The canonical event ledger owns history. The sealed origin owns inherited identity. Host events own objective world facts and objective outcomes. Subject events own commitments, goals, beliefs, concerns, and deliberate actions. The DecisionEngine remains the only deliberate action selector. Renderer output never acquires truth authority by generation alone. Retrieval changes accessibility, not truth. Projections remain disposable and rebuildable.

A promoted mechanism may contribute state, pressure, candidates, or a distinct non-deliberative emission. It may not create a second executive.

## Integration order

### I1. Narrow commitment pressure

Purpose: make existing open commitments causally relevant to action scoring without adding another selector.

Production change:
- extend `ActionCandidate` with explicit commitment-sensitive weights or an equivalent bounded declarative field,
- have `DecisionEngine` read open commitment descriptions,
- add positive or negative score contributions when preregistered keywords match,
- preserve the score receipt so every commitment contribution is auditable.

Required regression:
- no matching commitment produces exactly baseline behavior,
- unrelated commitments are neutral,
- confidentiality can suppress a disclosure candidate and support a refusal candidate,
- all selection still occurs in `DecisionEngine`,
- replay reconstructs the same open commitments and therefore the same candidate scores.

Ablation: candidates with empty commitment sensitivity reproduce v0.1 behavior.

### I2. Bounded planning

Purpose: preserve a goal and route across interruption, select one current plan step, and replan after failure.

Production state:
- a canonical goal root remains the semantic objective,
- plan execution state is reconstructable from canonical plan events,
- at most one plan is active per bounded planner instance,
- state includes plan ID, goal ID, objective, routes, route index, step index, status, and evidence/cause lineage,
- route and step state never becomes renderer-authored truth.

Suggested event family:
- `PLAN_CREATED`,
- `PLAN_ADVANCED`,
- `PLAN_REPLANNED`,
- `PLAN_COMPLETED`,
- `PLAN_ABANDONED`.

A smaller implementation may use one typed `PLAN_UPDATE` event if and only if replay and audit remain equally explicit.

Policy rule:
- the current plan step is converted to an ordinary `ActionCandidate`,
- plan utility competes with needs, relationships, commitments, concerns, habits, and safety,
- stronger pressure may postpone the plan,
- postponement does not silently erase it,
- host-reported outcome advances, replans, completes, or abandons the plan.

Neutral control: no relevant objective/evidence means no plan is manufactured.

Ablation: disabling the planner removes plan candidates while leaving goals and the rest of v0.1 intact.

### I3. Bounded private-cognition feedback

Purpose: allow private cognition to create bounded prospective pressure without turning model text into fact or autobiography.

Production admission:
- raw private thought is stored only as noncanonical renderer proposal,
- telemetry markers and machine identifiers are rejected before admission,
- accepted content becomes an uncertainty-marked concern, not a lived memory,
- identical active concerns do not stack,
- admitted intensity is bounded.

Production policy:
- active concern intensity modifies only candidates explicitly tagged for reflection/review,
- adjusted candidates go through the existing `DecisionEngine`,
- stronger homeostatic or other policy pressure can defeat reflection,
- concern state survives restart and replay.

Ablation: disabling private-cognition admission leaves ordinary concerns and v0.1 behavior unchanged.

### I4. Involuntary expression

Purpose: model reflexive expression without recoding it as deliberate speech.

Production event:
- add a distinct canonical involuntary-expression event kind,
- subject authority may own the expression, but payload must state `intentional: false`,
- payload contains qualitative trigger class and expression action, not hidden raw numeric state,
- the event must not update deliberate `last_action` or receive habit reinforcement as though chosen,
- a renderer may realize the expression linguistically, but the renderer does not decide whether the reflex occurred.

Policy rule:
- deliberate action selection happens normally,
- reflex evaluation is a separate bounded gate,
- both may occur in the same cycle without one replacing the other.

Ablation: with reflex evaluation disabled, deliberate policy is byte-for-byte unaffected.

### I5. TinyPersona perception adapter

TinyPersona is not integrated into the canonical core as world authority. A host adapter may filter candidate stimuli by modality, range, occlusion, and attention capacity before subjective framing.

The host retains objective stimuli. The subject receives only the accessible subset. The adapter cannot delete or rewrite host truth.

## Qualified infrastructure

The following may be integrated before or alongside behavior changes because they alter measurement rather than cognitive semantics:

- Kiki Subjective Frame receipts,
- Wayfarer renderer-swap comparison,
- Bicentennial matched-history controls,
- Kurzweil developmental counterfactuals,
- Memora remembering/forgetting evaluation,
- ContextEcho forked long-session drift probes.

Infrastructure must remain outside first-person subjective content unless the information would naturally be available to the character.

## Explicit non-integrations

The first v0.2 candidate must not include:

- Pretorius selective recall as a replacement for baseline retrieval, because the real frozen case showed zero quality gain,
- Digital Subject continuity influence as a separate organ, because existing relationship pressure already passed the target,
- offscreen catch-up as a default, because the current implementation remains over the preregistered cost gate,
- contextual plasticity as default, because complexity 0.42 exceeds the 0.35 automatic ceiling,
- Omnicore 6DE affect as default, because no production gap justifies it,
- MADMAN Crucible dynamics, because no bounded transplant has beaten simpler explicit mechanisms,
- npc-steering-plus or PersonaForge model-dependent mechanisms before compatible reproduction.

## Per-integration loop

For each I1 through I4:

1. branch from the last accepted integration head,
2. implement only one qualified mechanism,
3. add direct unit and authority tests,
4. run the inherited Frankenstein acceptance suite,
5. run the Bride real-baseline suite with the production implementation substituted for the lab challenger,
6. run the donor-removal ablation,
7. verify semantic replay and ledger integrity,
8. run Linux, Windows, and macOS CI,
9. update the promotion and experiment ledgers,
10. advance the candidate champion only if all gates pass.

A failure modifies the challenger, test fixture, or documented hypothesis only when evidence identifies the defect. The frozen prior champion is not weakened to make a transplant pass.

## Integrated v0.2 release gate

After all accepted integrations, compare the complete v0.2 candidate against frozen v0.1 and against the immediately previous candidate champion. The final suite must include:

- matched trust, betrayal, repair, and confidentiality histories,
- interrupted plans and failure-driven replanning,
- neutral quiet periods,
- private-cognition enabled and disabled arms,
- involuntary-expression neutral and trigger controls,
- restart and replay equivalence,
- renderer substitution with semantic-state invariance,
- long-session ContextEcho-style drift probes,
- Memora-style remembering and appropriate forgetting,
- Bicentennial-style matched histories and held-out transfer,
- Kurzweil-style developmental counterfactuals with leakage checks,
- cost and state-growth measurements.

v0.2 is accepted only if the integrated candidate is measurably stronger as a whole, not merely because several local donors individually passed.
