## Release-hardening defect found and corrected

The first compatibility run exposed an observability defect in `projection_digest()`: projection rows were ordered by SQLite `rowid`, so semantically identical projections could hash differently after replay when physical insertion order changed.

The release branch now normalizes projection rows by semantic row content before hashing. A dedicated regression deliberately changes physical relationship-row order without changing causal state and verifies that the projection digest remains stable.

The compatibility gate also carries an independent version-neutral semantic projection digest generated by the v0.1 fixture, so upgrade acceptance does not depend on either version's internal digest implementation.

## Interpretation boundary

This evidence establishes data and replay compatibility from the exact accepted v0.1 commit to the v0.2 release candidate under the representative populated fixture and both supported Python lines tested here. It does not claim compatibility with arbitrary unreleased historical database layouts or manually modified state stores.
