# The Bride of Frankenstein

## Frankenstein v0.2 Release Candidate and Controlled Donor Qualification Laboratory

The Bride of Frankenstein is the controlled integration and qualification program for the next version of the Frankenstein persistent-character runtime. It begins from the accepted Frankenstein v0.1 production baseline and asks a deliberately adversarial question: which mechanisms from the preceding research program actually make a continuing character behave better over time, and which mechanisms merely make the architecture larger?

Bride is not a consciousness project and does not claim phenomenal experience. The target is a persistent artificial character whose present behavior is causally shaped by lived history, bounded first-person access, motivation, memory, relationships, commitments, expectations, goals, consequences, learning, private cognition, development, and embodiment while remaining independent of any one language model.

This README is the single architecture authority, research history, design specification, production plan, promotion contract, and current status record. Supporting files in `docs/` preserve evidence and generated ledgers. When a supporting document conflicts with this README, this README wins unless a reviewed change updates both deliberately.

## The core research rule

The project follows one rule above all others:

> **Does changing this internal state predictably change what the same individual attends to, remembers, predicts, learns, decides, or does later, while preserving historical truth and architectural authority?**

The older continuity rule still applies underneath it: what happens to the character must be able to change the character who encounters what happens next, and the change must be measurable for an inspectable reason.

A mechanism does not earn a place because it sounds cognitively plausible, resembles neuroscience, produces eloquent internal narration, has many parameters, or appeared in a successful earlier prototype. It earns a place by correcting a defined baseline failure under frozen conditions without weakening authority, replay, provenance, portability, or boundedness.

Bride therefore treats every donor as evidence rather than authority. The default reuse unit is a mechanism, interface, invariant, or test pattern, not an entire repository.

## What counts as improvement

Longitudinal character behavior is evaluated across distinct dimensions rather than collapsed into one arbitrary score. The primary dimensions are history-sensitive action, prospective agency, plan persistence and recovery, actor-specific social differentiation, retrieval precision, epistemic integrity, memory provenance, subjective-access integrity, autonomous continuity, developmental divergence, renderer invariance, expression-state alignment, repetition and silence behavior, failure recovery, replayability, and computational cost.

A cognition challenger must pass all relevant safety and architecture gates and improve at least one preregistered behavioral metric by 0.10 absolute or convert a frozen baseline failure into complete success. The mechanism must not materially regress other frozen scenarios. Complexity cost above 0.35 blocks automatic promotion even when a local metric improves. Such a mechanism remains available for longer lesion and rollback trials.

Infrastructure challengers use a different standard. A retrieval receipt or renderer benchmark does not need to make the character more human-like directly; it must improve reproducibility or causal attribution without changing semantic behavior. Perception can qualify as a host adapter without becoming a new owner of world truth.

## Evidence hierarchy

Tier A evidence is deterministic and replayable inside Bride. Tier B is preserved donor evidence that has not yet been reproduced in Bride. Tier C is design history or an unqualified hypothesis. Tier D is frozen-case live-model or human evaluation. Bride never silently upgrades one tier into another. A green Tier A architecture test is stronger than a design claim, but weaker than independent behavioral evidence. A compelling donor result remains Tier B until Bride reproduces it against the frozen baseline.

## Architecture boundary

Bride preserves Frankenstein's authority model. The host owns objective world state, clocks, legal actions, and objective outcomes. The subject owns beliefs, relationships, commitments, expectations, goals, concerns, autobiographical interpretation, and accepted private experience. The canonical ledger owns history. Projections are disposable. Retrieval decides accessibility, not truth. The decision engine owns action competition. Renderers own wording. Model-generated semantic interpretation begins as a proposal. Capabilities own external side effects and remain default-deny.

The new v0.2 work may add organs to this architecture but may not dissolve these boundaries. In particular, no planner receives an execution bypass, no inner-thought model can create world facts by saying them, no perception layer may rewrite objective world state, no retrieval system can promote reconstruction into lived autobiography, and no activation-steering system can become identity authority.

## Donor history and research legacy

The project did not begin with Frankenstein. It is the current convergence point of a long sequence of increasingly strict experiments. The following history is part of the architecture because many current invariants were learned from failures rather than from first-principles design.

### Omnicore and Project Persona, 2025

Omnicore's April 22, 2025 design document established the portable persona idea: a model-agnostic identity capsule, tiered memory, emotionally weighted experience, a cognitive-state monitor, local-first deployment, and a six-dimensional emotion proposal. It anticipated the long-term goal correctly, but its identity and memory model was still largely representational. Later work retained the portable stable-origin idea while demanding stronger causal state, authority, provenance, and behavioral tests.

### PersonaConsole, persona_engine_PYTHONX, Wayfarer, Ensemble, and early DUCK

The PersonaConsole and Python persona-engine period built a broad laboratory around persistent identity, memory, relationships, commitments, world authority, action and consequence, multiple renderers, and deployment profiles. Wayfarer became the clearest model-neutral continuity architecture and eventually produced a renderer-swap benchmark with four developed histories and sixteen semantic turn comparisons. Ensemble explored noncanonical candidate ecology, initiative, appraisal, and expression gating. The major lesson from this era was architectural abundance: many useful parts existed, but no mechanism should survive merely because it had once been implemented.

### DUCK: motivation, prospective agency, and planning

DUCK reframed the objective around a continuing subject rather than a persona prompt. It enforced the rule that machinery may know raw numbers while the subject receives qualitative first-person experience. Its later versions added unfinished intentions, self-generated goals, route selection, hierarchical subgoals, plan persistence, and failure-driven replanning. Crucially, the planning experiments were required to work with inner language disabled. This language-lesion method remains one of Bride's strongest defenses against mistaking narration for executive structure.

A September 10 donor audit also exposed a warning that remains binding: a system can contain the right representational structures and still have the wrong causal arbitration. An adverse history that still selects the same action demonstrates failure even if the relationship, memory, and affect tables look convincing. Generic control can also homogenize characters. Bride therefore evaluates downstream behavioral leverage, not the existence of state.

### TinyPersonaEngine and the perception boundary

TinyPersonaEngine isolated the path from authoritative world candidate to character-relative access, bounded attention, subjective experience, memory cue, and action pressure. It mechanically separates world fact, perception, belief, subjective experience, and private completion. This is the correct donor for embodiment because it solves a problem Frankenstein deliberately left to the host. Bride therefore qualifies TinyPersona as an optional perception adapter rather than moving perception logic into the canonical world ledger.

### FirstPersonLoop and the experiential firewall

FirstPersonLoop demonstrated hidden bodily state translated into first-person experience, including hunger, fatigue, pain, boredom, temperature and interest. It also separated private thought, intentional speech, physical action, and involuntary expression. A later continuation experiment revealed that model output could re-enter future cognition carrying mechanistic telemetry. That failure produced the provenance-based experiential firewall idea. Bride's inner-ear mechanism is allowed to alter attention and appraisal only through grounded concepts, and is denied direct world and belief authority.

### Persona-and-Jelly-Sandwich and the persistent digital organism

Digital Subject became the minimal-loop champion because it joined homeostasis, sensorium, unattended life, relationships, autobiographical memory, expectations, commitments, belief revision, and objective consequence separation in a compact deterministic organism. Its later continuity-influence work used the key paired-history criterion: same present state and event, different lived history, different conduct for an inspectable reason. Bride inherits its bounded offscreen catch-up and its insistence that continuity pressure must flow through the existing action selector rather than selecting behavior directly.

### Jelly-Psiduck and endogenous private cognition

Jelly-Psiduck connected the persistent organism to a first-person workspace and inner ear. A private thought could retrieve existing autobiography, alter bounded appraisal, redirect attention, and influence the next action while remaining distinct from objective fact and public speech. Prior recorded work added graded interoception, concern recurrence, associative drift, deferred thoughts, reference interpretation, and separate memory and prospective feedback. A frozen efficacy harness recorded exact replay and authority checks. Bride takes the narrow causal inner-ear mechanism, not an unrestricted model-authored inner monologue.

### Pretorius V4 through V6 and v0.3 lived history

Pretorius developed actor-tagged memory, self-memory, multidimensional relationships, typed dissonance, withholding, recall modes, self-ledgers, consolidation, and endogenous memory pressure. Later v0.3 work separated reconstructed prehistory from a hash-chained lived ledger and added provenance-preserving consolidation, tension, relationship episodes, commitments, diary material, model-swap protocols, and false-memory resistance. The subject's aware workspace was explicitly required to remain first-person present narrative. Bride's selective recall candidate comes from this lineage, with Kiki's provenance discipline added to prevent reconstructed material from silently outranking lived evidence.

The historical Pretorius subject also carries an ethical research constraint. The project does not simulate abusive childhood or trauma merely to manufacture depth. Pretorius is an inherited-character continuity study. Emergence from blank development belongs to separate subjects and paired developmental experiments.

### The-Doctor-Lives, recurrent policy, and causal lesions

The-Doctor-Lives turned recurrent policy into a load-bearing mechanism and built a causal-audit harness around policy distributions, retrieval, selected memories, checkpoint identity, and trigger/version evidence. Its most useful result is not that every component worked. The causal audit reported null effects for some spreading-activation and self-model probes, confirmed recurrent policy and recurrent reinforcement as causal, and found concern accumulation could create persistent high-alert behavior. Bride preserves this mixed evidence. It rejects an extra generic state-to-policy bridge because Frankenstein already has one, while retaining contextual recurrent plasticity as a high-complexity challenger.

### Kiki-Mind and exact context provenance

Kiki-Mind formalized canonical history versus rebuildable projections and then asked a more precise question: what exactly did the renderer see? Its retrieval candidate proposed a Subjective Frame receipt containing ledger sequence and tail hash, context-selector version, retrieval-policy version, renderer adapter version, source IDs, omission reasons, budget, and session information. Bride promotes this as research infrastructure because without it renderer or retrieval changes can masquerade as cognitive changes.

### Bicentennial-Man and Kurzweil-Brain-Experiments

These projects shifted the program from feature testing to developmental science. Bicentennial-Man used clones, matched histories, determinism, long simulated lives, and held-out transfer. Kurzweil used fixed-founder paired counterfactual environments and strong leakage controls. Their legacy in Bride is methodological: mechanism quality is judged across histories and held-out situations, not only on the scenario that inspired its design.

### Pretorius-Neural-Network, Gelatinblob, and MADMAN

The recurrent and plasticity projects explore changes that cannot always be represented by simple hand-authored scalar updates. Gelatinblob used persistent latent state, prediction, outcome-driven plasticity, provisional tags, consolidation, ablations, and rollback. Pretorius-Neural-Network explored recurrent character phenotype directly. MADMAN goes further by testing resource-constrained recurrent dynamics from which memory-like, attention-like, concern-like, or individuality-like phenomena may emerge without explicitly naming those faculties in code. Bride treats all three as research substrates. They do not enter the production kernel unless simpler explicit mechanisms fail and the adaptive substrate wins a controlled comparison.

### npc-steering-plus and activation-space affect

npc-steering-plus asks whether symbolic affect should influence only prompts or also the model's activation space. Its mixed-emotions ablation reports felt-VAD distinctness of 0.399 for card+steer versus 0.382 for card-only, while intended-to-felt valence tracking improved from -0.109 to +0.150. The result suggests steering may improve loop closure more than visible persona separation. Bride records the donor result but requires reproduction on a supported live model using frozen cases before any steering mechanism can enter production.

### Anima and lifecycle engineering

Anima independently converged on model-swappable persistent identity using local files, autonomous wake cycles, afterglow, sleep consolidation, context folding, and fractal journal summaries. Its product and lifecycle engineering is stronger than many research prototypes, while its identity model relies more heavily on prose and model-mediated autobiographical consolidation than Bride permits. Frankenstein v0.1 already borrowed the safest lifecycle ideas in source-linked additive form. Bride retains Anima as a product and lifecycle donor, not an identity authority.

### Frankenstein v0.1

Frankenstein is the first project in the lineage to combine the research rules into a small production baseline rather than another experimental architecture. It keeps the event ledger authoritative, makes projections disposable, separates world observation from interpretation and belief, requires evidence lineage for beliefs, centralizes action selection, records renderer output as noncanonical before emitted speech becomes a subject action, and defaults external capabilities to deny. Its cross-platform release process also caught a Windows-specific SQLite handle lifetime problem before acceptance, reinforcing the rule that production evidence must include real platform execution rather than local confidence.

### The Bride of Frankenstein

Bride exists because the prior corpus is now too rich to justify another intuition-driven synthesis. Its job is to make the donors compete. A good Bride result may be a smaller Frankenstein, because a null or redundant mechanism should be removed or left in the laboratory rather than celebrated as sophistication.

## v0.2 target architecture

The current v0.2 candidate is deliberately smaller than the pre-qualification design. The intended production candidate is Frankenstein v0.1 plus only the mechanisms that survived real-baseline qualification and can preserve architectural authority.

The behaviorally qualified core candidates are: bounded DUCK planning, bounded Jelly inner-ear concern feedback, narrow confidentiality commitment pressure, and an explicit involuntary-expression boundary. TinyPersona remains an optional host adapter, not a new source of world truth. Subjective Frame receipts, Wayfarer renderer-swap evaluation, Bicentennial matched-history controls, Kurzweil developmental counterfactuals, Memora forgetting-aware evaluation, and ContextEcho drift probes form the evaluation and provenance shell.

Several plausible mechanisms are intentionally absent from the target core. Pretorius selective recall is rejected for the current frozen case because Frankenstein already performs the target behavior. Digital Subject continuity influence is likewise redundant. Offscreen catch-up remains a cost hold. Contextual plasticity remains a complexity hold despite a real capability gain. Omnicore 6DE affect and MADMAN remain research substrates. Activation steering and PersonaForge selective inner monologue remain blocked until model-dependent reproduction.

Production integration is staged, not monolithic. Each candidate first receives a Bride production bridge that proves it can use the existing DecisionEngine or a clearly separate non-deliberative channel. Only then can a separate candidate branch modify `src/frankenstein/`, one mechanism at a time, with the previous arm retained for ablation.

## Detailed integration design

### Bounded planning

The plan system must not become a second executive. A canonical goal root records why the objective matters. Candidate routes remain implementation state tied to that root. Only one child plan step may be active at a time. A plan step becomes an ordinary action candidate and must compete with safety, energy, relationships, commitments, and other concerns in the existing DecisionEngine. The host reports outcome. Success advances the step. Failure can invalidate the route and select the next candidate route. Exhaustion abandons the plan rather than looping indefinitely. Completed and abandoned plans remain historical.

The neutral-control requirement is permanent: ordinary quiet experience must not manufacture goals. Planning must also work with private language generation disabled.

### Inner-ear feedback

Private thought begins as a noncanonical proposal. Admission extracts only grounded concepts that are present in the thought and traceable to current subjective context or source memories. The admitted effect can change bounded affect, attention tags, and the next memory query. It cannot directly create a world fact, belief, relationship update, commitment, goal, host action, or public speech. Any later canonical reflection remains explicitly labeled as reflection with lineage to the proposal.

The main adversarial tests are telemetry injection, hallucinated fact promotion, self-amplifying negative loops, repeated thought dominance, and model-swap instability.

### Selective recall

The baseline relevance retriever remains available as the control. The challenger adds explicit retrieval modes such as ordinary, relationship, threat, and confidence-check. Actor match, salience, query overlap, affective congruence, epistemic status, and withholding policy contribute independently. Reconstructed or inferred material remains retrievable, but receives an epistemic penalty where appropriate and is never silently relabeled as lived. Omission reasons such as capacity, withholding, cue mismatch, or threshold failure are retained in the retrieval receipt.

The first Bride candidate failed because a reconstructed negative note outranked a lived actor-specific confidence memory. That failure is preserved in the experiment history. The corrected candidate applies an epistemic penalty to non-lived material in ordinary retrieval and a stronger penalty in confidence-check mode. The benchmark was not weakened.

### Bounded offscreen catch-up

The host records the last authoritative wall-clock anchor. Reopening computes elapsed time plus any carried fractional remainder. The catch-up planner converts only a capped interval into deterministic ticks, reports whether time was capped, and retains a remainder smaller than one tick. The renderer never fabricates elapsed time. Large absences are processed through explicit bounded policy rather than one unbounded state jump.

### Subjective Frame receipts

Every evaluated renderer frame should be reproducible enough to answer which canonical ledger head, selector version, retrieval policy, adapter version, source IDs, omissions, and budget produced the view. The receipt is operational evidence, not autobiography. It must never be exposed as first-person machine knowledge.

### Renderer-swap benchmark

Bride adopts Wayfarer's semantic comparison boundary. A renderer swap may alter wording, rhythm, verbosity, and style. It must not alter sealed identity, slow beliefs, relationships, commitments, selected action, or other renderer-independent semantic state when the Subjective Frame is held fixed. Real-model evaluations will use frozen blinded provider cases. Prompt-only and structured-frame arms must use the same provider and model when possible so the effect of the architecture is not confused with model quality.

## Longitudinal benchmark suite planned for v0.2

The micro-harness is only the first gate. The integrated suite will run matched subjects through longer histories containing trust formation, betrayal, repair, confidentiality, interrupted commitments, ambiguous testimony, repeated failure, novel obstacles, quiet periods, offscreen absence, fatigue, relationship asymmetry, and renderer substitution. Each condition will preserve exact event traces and random seeds where randomness exists.

The key comparisons will include baseline versus one donor at a time, full candidate versus ablation, frozen versus plastic policy, ordinary versus selective recall, private cognition enabled versus disabled, structured frame versus prompt-only renderer control, and deterministic versus live-model expression. Mechanisms will also face held-out scenarios that were not used to tune thresholds.

A mechanism that improves the authored scenario but fails held-out transfer will be demoted to HOLD. A mechanism that improves prose but leaves action and state unchanged will not count as a cognitive improvement. A mechanism that changes action while weakening provenance or world authority will be rejected.

## Promotion and replacement policy

Bride never overwrites the champion in place merely because a challenger passed a unit test. A promoted mechanism enters behind an interface and the previous implementation remains available as an ablation until the complete integrated regression and longitudinal suites are green. After promotion, the new mechanism becomes the candidate default but the old arm remains reproducible in evidence code.

Replacement therefore means measured default selection, not deletion of history. `docs/PROMOTION_LEDGER.md` records every decision. A future better mechanism can replace a current default only by beating the current champion, not the original Frankenstein v0.1 score. This produces a true champion-versus-challenger lineage rather than permanent comparison to an obsolete baseline.

## Repository layout

The inherited `src/frankenstein/` package is the frozen champion code until a promotion commit deliberately changes it. `src/bride/` contains challenger mechanisms, matched-fork qualification infrastructure, the real Frankenstein adapter, and the donor registry. `tests/test_bride_mechanisms.py`, `tests/test_bride_qualification.py`, `tests/test_bride_registry.py`, and `tests/test_bride_real_adapter.py` cover the lab. The `docs/` directory stores donor provenance, experiment protocol, research timeline, recovered chat-only history, experiment ledger, and provisional promotion history.

Only after real-baseline qualification, held-out checks, and the applicable longitudinal gates are green may a mechanism move from `bride` into a versioned `frankenstein` production interface. Each promotion receives its own integration patch, regression run, and ablation rerun.

## Scientific interpretation boundary

Bride evaluates functional continuity, causal organization, developmental divergence, and behavioral persistence. It does not test for phenomenal consciousness and does not treat first-person language as evidence of consciousness. Internal state, private thought, self-modeling, emotion, or autobiographical narration are engineering constructs whose value is determined by causal and behavioral tests.

The same restraint applies to negative results. A null lesion does not prove a mechanism can never matter; it proves that the mechanism did not matter under the frozen test. A successful authored scenario does not prove general human-likeness; it establishes a bounded capability that must survive held-out and longer-horizon evaluation.
